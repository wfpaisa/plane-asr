# Plan: troceado automático de audios largos

## Causa raíz del error
No es de la extensión: `transcribe-cli` con Qwen3-ASR trunca la salida a **256 tokens por invocación**. Un audio de 72.9 s de habla continua los supera → transcripción incompleta y exit code != 0, que la extensión reporta como error. Solución: partir el WAV en trozos cortos antes de transcribir, de modo que ningún trozo llegue al límite.

## Cambios por archivo

### 1. NUEVO `src/extension/audio-chunker.ts` (dependencias cero)
Función pura `sliceWav16kMono(srcPath: string, seconds: number, outDir: string): string[]`:
- Lee el WAV con `Gio.File.load_contents` (archivos pequeños, ~32 KB/s → seguro síncrono en main thread).
- Parsea el header RIFF/WAVE robustamente: localiza el chunk `data` escaneando en vez de asumir offset 44 (insurance ante chunks extra), valida `audioFormat==1` (PCM) y `bitsPerSample==16`.
- `samples = dataBytes / 2`; `chunkSamples = seconds * 16000`. Troza el bloque `data` en fragmentos de `chunkSamples` (el último más corto).
- Por cada trozo sintetiza un header RIFF de 44 bytes nuevo (16 kHz, mono, s16) + los bytes del trozo, y lo escribe como `recording_<stamp>_part<n>.wav` en `outDir`.
- Devuelve el array de rutas. Lanza si el formato no es el esperado (el caller hace fallback).
- Casos límite: 0 muestras → lanza; audio más corto que `seconds` → devuelve array de **1 elemento** (el caller decide saltar el bucle).

### 2. `src/util/paste.ts` — `pasteAtCursor` devuelve `Promise<void>`
- Hoy es `void` con un `GLib.timeout_add` interno de 300 ms para restaurar el portapapeles.
- Cambio la firma a `pasteAtCursor(text: string): Promise<void>` que **resuelve tras el restore** (cuando el `timeout_add` ejecuta `SOURCE_REMOVE`). Así el servicio puede `await` entre pegados consecutivos sin que se pisen.
- `copyToClipboard` se queda igual.
- La espera entre trozos queda localizada en un solo sitio (evita un timeout duplicado en el servicio).

### 3. `src/config/settings.ts` + `schemas/...gschema.xml` (mantener en sync)
Dos claves nuevas:
- `chunk-enabled` (bool, **default `true`**) → `SETTINGS_KEYS.CHUNK_ENABLED`
- `chunk-seconds` (int, **default `10`**) → `SETTINGS_KEYS.CHUNK_SECONDS`

### 4. `src/extension/asr-service.ts` — orquestación del troceado
En `_stopAndTranscribe()`, tras `recorder.stop()` y setear `LAST_AUDIO_PATH`:
1. Leer `chunk-enabled` y `chunk-seconds`. Si está activado, llamar a `sliceWav16kMono(...)` dentro de try/catch; si falla o devuelve 0, **fallback** a transcribir el archivo original entero (no bloquear al usuario).
2. Si devuelve exactamente **1 trozo**, transcribir la ruta **original** (comportamiento byte-igual al actual, sin reescribir el WAV).
3. Si devuelve **>1 trozos**, bucle secuencial:
   - `const r = await this._transcriber.transcribe(chunkPath)` por cada uno. El `_proc`/`forceExit` del Transcriber ya resetea entre llamadas, así que cada iteración es una invocación limpia.
   - Si `r.cancelled` → `setState(Idle)` y salir (cancelar mata el trozo en curso y el bucle se detiene).
   - Acumular `r.text.trim()` en `texts[]`.
   - **Modo `paste`**: pegar cada trozo en cuanto llega con `await pasteAtCursor(piece)` (espera la restauración del portapapeles → no hay solapamiento) y, si vale la pena, mostrar progreso en el label del menú ("Transcribiendo 2/5…").
   - **Modo `clipboard`**: no pegar nada durante el bucle; acumular todo.
4. Al terminar: `full = texts.join(' ')`, `set_string(LAST_TEXT, full)`. En modo clipboard copiar `full` de una vez. Notificar y `setState(Idle, {text: full})`.
5. **Limpieza**: borrar los WAV de trozos (los `*_part*.wav`) al final del bucle tanto en éxito como en error (finally), conservando el WAV original referenciado por `LAST_AUDIO_PATH`.

El método `_dispatch` actual se elimina/reemplaza por esta lógica inline (la bifurcación paste-vs-clipboard ahora vive en el bucle). El Transcriber **no cambia**.

### 5. `src/prefs/index.ts` — UI
Nuevo `Adw.PreferencesGroup` "Audios largos" con:
- `Adw.SwitchRow` "Trocear audios largos" → bind `chunk-enabled`.
- `Adw.SpinRow` "Segundos por trozo" con `Gtk.Adjustment(10, 5, 60, 1, 5, 0)` → bind `chunk-seconds`; `sensitive` ligado al switch (se deshabilita si el switch está off). `Adw.SpinRow` existe desde libadwaita 1.4 (GNOME 46+), disponible en GNOME 50.

### 6. `src/extension/indicator.ts` — progreso opcional
Exponer el progreso del troceado reutilizando el estado existente: en `AsrState.Transcribing`, el label del `_recordItem` puede mostrar "Transcribiendo i/n" si el contexto lo trae. Mínimo invasivo: añadir un campo opcional `progress` a `AsrChangeContext` y pintarlo si viene. Si complica, se deja el label "Cancelar transcripción" actual — no es bloqueante.

## Gates de calidad (según AGENTS.md)
- `pnpm run build` (tsc strict) debe pasar.
- `pnpm run lint` (eslint) debe pasar.
- `glib-compile-schemas schemas` (lo hace `make pack`) tras editar el schema.
- No añadir inicializadores de campo con side effects (regla `useDefineForClassFields: false`); asignar dentro de métodos.
- Imports internos con extensión `.js`.

## Lo que NO cambia
- `transcriber.ts` (contrato single-run intacto), `recorder.ts`, `asr-backends.ts`, `index.ts`, el keybinding, el flujo IDLE→RECORDING→TRANSCRIBING→IDLE.
- El behavior para audios cortos y/o chunking desactivado: idéntico al actual.

## Notas de despliegue
`pnpm run build && pnpm run lint` → `pnpm run setup` → cerrar sesión/entrar (Wayland). Para verificar: grabar >30 s, confirmar en `journalctl --user -b /usr/bin/gnome-shell | grep planeasr` (con debug logging on) que se lanzan N invocaciones del CLI de N segundos cada una y que la transcripción final ya no lleva el warning de truncamiento.
