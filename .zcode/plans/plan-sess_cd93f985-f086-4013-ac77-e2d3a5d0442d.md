## Objetivo

Diferenciar el click izquierdo del derecho en el indicador del panel:

- **Click izquierdo (primario)** → mostrar la notificación actual (`Main.notify(_('Plane ASR is active'))`), **sin** abrir el menú.
- **Click derecho (secundario)** → abrir el menú contextual con dos opciones:
    1. **Iniciar/detener grabación** (etiqueta estática) → dispara la misma notificación.
    2. **Settings** → abre la ventana de Preferencias existente vía `openPreferences()`.

## Por qué hay que interceptar `menu.toggle` (no `button-press-event`)

En GNOME 50, `PanelMenu.Button` abre el menú mediante una **acción** `Clutter.ClickGesture` (`this._clickGesture`), no mediante la señal `button-press-event`. Ese gesto dispara `this.menu.toggle()` con **cualquier** botón y corre por una ruta distinta a las señales de actor, así que capturar/devolver `Clutter.EVENT_STOP` en `button-press-event` **no** lo frena. La extensión de referencia (`color-picker@tuberry`, GNOME 50) lo resuelve envolviendo `menu.toggle` y revisando `this._clickGesture.get_button()` + `.state`. Replicamos ese patrón probado.

## Cambios

### 1. `src/extension/indicator.ts` (cambio principal)

- Importar `Clutter` y `Gio` (este último para el `Gio.Settings`/nada nuevo; en realidad solo `Clutter`).
- `Indicator._init()` recibe la `Extension` como parámetro (ej. `_init(extension)`) para poder llamar `openPreferences()`.
- Sustituir el item único actual por dos items del menú:
    - `PopupMenu.PopupMenuItem(_('Iniciar/detener grabación'))` → al activarse cierra el menú y lanza la notificación.
    - `PopupMenu.PopupMenuItem(_('Settings'))` → al activarse cierra el menú y llama `this._extension.openPreferences()`.
- Método privado `_toggleMenuForRightClick()` (o inline) que **envuelve** `this.menu.toggle`:
    ```ts
    const originalToggle = this.menu.toggle.bind(this.menu);
    this.menu.toggle = () => {
        // El gesto de click del PanelMenu.Button ya está COMPLETED aquí.
        if (
            this._clickGesture.state === Clutter.GestureState.COMPLETED &&
            this._clickGesture.get_button() === Clutter.BUTTON_PRIMARY
        ) {
            Main.notify(_('Plane ASR is active')); // click izquierdo
        } else {
            originalToggle(); // click derecho (o teclado/otros) abre el menú
        }
    };
    ```
- Extraer la notificación en un método `_notifyActive()` para reutilizarla (click izq + item del menú).

### 2. `src/extension/index.ts`

- En `enable()`, pasar `this` (la extensión) al constructor: `this._indicator = new Indicator(this);`.

### Archivos NO modificados

- `src/prefs/index.ts` — se queda tal cual (abre las preferencias existentes con Animated feedback / Inner padding, según decisión del usuario).
- `src/config/settings.ts` y schemas — sin cambios (no se necesitan claves nuevas).
- `extension.ts` / `prefs.ts` (shims raíz) — sin cambios.

## Tipado / verificación

- `Clutter.ClickGesture.state` (`GestureState`) y `get_button()` existen en `@girs/clutter-18`.
- `Extension.openPreferences(): void` existe en `@girs/gnome-shell@50`.
- Compilar con `pnpm run build` (tsc) y `pnpm run lint` como gates de corrección (no hay test runner).

## Entrega

Después de editar, ejecutaré `pnpm run build` y `pnpm run lint` para confirmar que compila y pasa lint. No reinstalaré la extensión ni reiniciaré el Shell (eso lo hace el usuario con `make install` / Alt+F2 `r` / relogin), salvo que lo pidas.

## Limitaciones conocidas

- Como en color-picker, abrir el menú por teclado/atajo de accesibilidad también caerá en la rama `originalToggle()` (comportamiento correcto: solo el click izquierdo del ratón va a la notificación).
- El estado de grabación es solo visual por ahora (la notificación dice "is active" siempre); cuando se implemente el ASR real, el item "Iniciar/detener grabación" cambiará a la etiqueta dinámica real.
