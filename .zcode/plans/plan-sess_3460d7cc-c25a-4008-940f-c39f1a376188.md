## Resumen del proyecto

Extensión de GNOME Shell en TypeScript (`planeasr@wfelipe.com`) con código de plantilla y estructura plana. Se reorganiza con un layout modular (`src/`) y se limpia el código plantilla, manteniendo compatibilidad con el sistema de build de GJS.

## Estructura propuesta

```
plane-asr/
├── src/                          # código fuente TypeScript modular
│   ├── ambient.d.ts              # (movido desde la raíz)
│   ├── extension/
│   │   ├── index.ts              # export default class PlaneAsrExtension
│   │   └── indicator.ts          # clase Indicator (limpia "My Shiny Indicator")
│   ├── prefs/
│   │   └── index.ts              # export default class PlaneAsrPreferences
│   └── config/
│       └── settings.ts           # claves/tipos del GSchema centralizadas
├── schemas/
│   └── org.gnome.shell.extensions.planeasr.gschema.xml   # (sin cambios)
├── extension.ts                  # entry point raíz: re-exporta desde src/extension
├── prefs.ts                      # entry point raíz: re-exporta desde src/prefs
├── metadata.json                 # (sin cambios)
├── stylesheet.css                # (sin cambios)
├── tsconfig.json                 # actualizado
├── package.json                  # scripts alineados
├── Makefile                      # dependencias y globs actualizados a src/
├── LICENSE                       # NUEVO (GPL-2.0-or-later)
├── .editorconfig                 # NUEVO
├── .gitignore                    # limpieza menor
└── README.md                     # actualizado
```

## Detalles de implementación

**1. Layout modular bajo `src/`**

- `src/extension/indicator.ts`: clase `Indicator`, renombrada la etiqueta `"My Shiny Indicator"` -> `"Plane ASR"`, y el item de menu/notificacion a algo coherente.
- `src/extension/index.ts`: `export default class PlaneAsrExtension`.
- `src/prefs/index.ts`: `export default class PlaneAsrPreferences`. Se conservan las claves del GSchema (`animate`, `padding-inner`) para no romper el schema, cambiando titulos/subtitulos de UI a neutros.
- `src/config/settings.ts`: constantes tipadas para las claves de GSchema.

**2. Entry points raiz delgados** (GJS requiere `extension.js`/`prefs.js` en la raiz del bundle)

- `extension.ts` -> `export { default } from './src/extension/index.js';`
- `prefs.ts` -> `export { default } from './src/prefs/index.js';`
- Con `module: NodeNext`, la re-exportacion usa extension `.js`.

**3. `tsconfig.json`**

- `"files": ["extension.ts", "prefs.ts"]` (arrastran el arbol `src/`).
- `"include": ["src/ambient.d.ts"]`.

**4. `Makefile`**

- Cambiar el prerequisito `*.ts` a `$(wildcard src/**/*.ts) extension.ts prefs.ts src/ambient.d.ts`.

**5. Archivos nuevos**

- `LICENSE`: texto GPL-2.0-or-later.
- `.editorconfig`: indent 2 espacios, LF, final newline.

**6. Limpieza**

- `.gitignore`: quitar patrones rotos (`_.log`, el patron `report.[0-9]_...`).
- `README.md`: anadir seccion "Project structure".

## Verificacion

- `pnpm run build` genera `dist/extension.js` y `dist/prefs.js` sin errores.
- `make clean && make all` compila correctamente.
- `dist/extension.js` conserva el `export default`.

## Lo que NO se toca

- `metadata.json`, `pnpm-lock.yaml`, `schemas/*.gschema.xml`, `stylesheet.css`.
- El schema GSettings (claves y tipos) para no invalidar config existente.
- No se anade logica ASR real (fuera de alcance: "renombrar y limpiar").
