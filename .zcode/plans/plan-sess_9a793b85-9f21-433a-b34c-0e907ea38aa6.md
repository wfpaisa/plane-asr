## Contexto validado

El truncamiento a 256 tokens NO fue por duración (el audio era de 72.9 s; el modelo admite 5218.6 s) sino por el **límite de generación *hardcodeado*** en `transcribe.cpp` (`k_max_new = 256`, no configurable). Trocear externamente es la **única** vía para Qwen3-ASR (no hay streaming nativo, no hay timestamps, no hay `initial-prompt`). La implementación de chunks ya hecha es correcta.

Para el solapamiento, como Qwen3-ASR **no produce timestamps** (`max_timestamp_kind = NONE`), la dedup **debe** ser por coincidencia difusa de texto en el borde (la opción de timestamps es imposible aquí).

## Cambios

### 1. NUEVO `src/util/text-merge.ts` (dedup difuso, puro, sin imports GNOME)
Función `dedupChunkJoin(prev, curr, maxWords): string` que devuelve el sufijo de `curr` sin el prefijo que duplica la cola de `prev`:
- Tokeniza por espacios; normaliza cada token (minúsculas + quitar puntuación de borde con `\p{L}\p{N}` unicode, para no romper ñ/acentos).
- Busca el **mayor** solape `k` (de `maxWords` a 1): lo acepta si es **exacto**, o si `k >= 3` y el ratio de coincidencia `>= 0.7` (tolera ~30% de variación del ASR en el borde). Solapes cortos requieren exactitud (evita falsos positivos en frases comunes como "y el").
- Si no hay coincidencia convincing → devuelve `curr` tal cual (duplicar es más seguro que borrar texto legítimo).
- Solo se invoca cuando el solapamiento está activado: en chunks contiguos (overlap 0) **no** se llama, porque coincidencias casuales borrarían palabras legítimamente repetidas.

### 2. `src/extension/asr-service.ts` — worker `_runStream` con solapamiento
- `StreamSession`: quito `consumed` (pasa a ser variable de bucle), añado nada nuevo en la sesión (`lastFull` queda como local del bucle). Mantengo `dataOffset`, `texts`, `ended`, `cancelled`.
- Cálculo: `overlapSamples = clamp(overlapSec*SR, 0, chunkSamples - SR)` (garantiza ≥1 s de audio nuevo por chunk); `step = chunkSamples - overlapSamples`; `maxOverlapWords = overlap>0 ? max(3, ceil(overlapSec*5)+2) : 0`.
- Bucle con ventanas solapadas: `start=0`, `covered=0`. Cada chunk = `[start, start+chunkSamples)`; el siguiente empieza en `start+step` (relee los últimos `overlapSamples`). Condición de fin: `break` cuando `ended` y `available <= covered` (todo el audio ya transcrito al menos una vez). El resto final más corto se maneja igual que ahora.
- Tras transcribir cada chunk (`piece`):
  - `emitted = (overlap>0 && lastFull) ? dedupChunkJoin(lastFull, piece, maxOverlapWords) : piece`
  - `lastFull = piece` (se guarda el texto **completo** del chunk, no el recortado, para que el siguiente solape calcule contra el audio real).
  - Si `emitted` es vacío (todo el chunk era solape) → `continue` sin emitir (pero `lastFull` ya actualizado).
  - paste: pega solo `emitted` (con espacio si no es el primero). clipboard: `[...texts, emitted].join(' ')`.
- Cuando overlap = 0, `step = chunkSamples`, ventanas contiguas, `emitted = piece` siempre → **comportamiento idéntico al actual** (sin riesgo de borrar texto).

### 3. Ajustes de configuración (solapamiento configurable)
- `src/config/settings.ts`: añadir `CHUNK_OVERLAP_SECONDS: 'chunk-overlap-seconds'`.
- `schemas/org.gnome.shell.extensions.planeasr.gschema.xml`: nueva clave `chunk-overlap-seconds` (int, **default 1**, rango gestionado en UI). Descripción: segundos de solape entre chunks para no cortar palabras en los bordes; 0 lo desactiva.
- `src/prefs/index.ts`: nuevo `SpinRow` "Overlap seconds" (0–5, step 1) en el grupo "Long recordings", ligado a la clave, con `sensitive` sincronizado con `chunk-enabled` (como ya hace `chunk-seconds`).

### 4. Sin cambios
- `audio-chunker.ts`: `writeWavChunk` ya recibe `sampleStart`/`sampleCount` arbitrarios → no hay que tocar nada.
- `transcriber.ts`, `recorder.ts`, `indicator.ts`, `asr-backends.ts`: intactos.

## Notas / trade-offs
- Default overlap = **1 s** (alineado con el objetivo de arreglar palabras cortadas; barato a 88x realtime). El usuario puede poner 0 para desactivar.
- Limitación conocia del dedup por texto (no por timestamps): si el ASR transcribe el borde de forma muy distinta entre los dos chunks, la coincidencia puede fallar y se duplica ese fragmento (seguro: duplicar > borrar). Es inherente a que Qwen3-ASR no da timestamps.
- No se toca transcribe.cpp: el enfoque mantiene la dependencia externa sin bifurcar.
