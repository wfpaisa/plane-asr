# Plan: Buscador/descargador de modelos + backend CPU/Vulkan + configs de Handy

## Resumen del análisis

**Handy-main** usa `transcribe-cpp` como librería Rust _en proceso_ (con Vulkan/Metal enlazado). **plane-asr** invoca binarios externos (`transcribe-cli`, `whisper-cli`) vía `Gio.Subprocess`. Por tanto, el control del backend se hace **inyectando flags CLI**, no enlazando nada. Hallazgos técnicos críticos verificados:

- **No existe `-ngl` en ninguno de los dos CLIs** (es flag de llama.cpp). La ofload a GPU es automática.
- **transcribe-cli**: `--backend {auto,cpu,vulkan,...}` + `--device N` (índice del registro, 0=auto). VAD no existe.
- **whisper-cli**: `-dev N`/`--device N` + `-ng`/`--no-gpu`. VAD con `--vad`.
- **`gi://Soup` 3.0** está disponible en runtime (dep de gnome-shell); falta `@girs/soup-3.0` para tipos.
- **URL HF**: `https://huggingface.co/{repo}/resolve/main/{file}`, soporta `Range:` (resume) y el `oid` del árbol API es el SHA-256.

## Decisiones de diseño

1. **Catálogo embebido + auto-detección**: archivo `data/model-catalog.json` con 18 modelos curados GGUF (parakeet, nemotron, canary, whisper, qwen3-asr, cohere, voxtral). Offline-first, sin red para listar.
2. **Backend de cómputo completo**: selector Auto/CPU/Vulkan + auto-detección de VRAM con `vulkaninfo --summary` para estimar `n`-device óptimo.
3. **Features semánticas por backend**: cada `AsrBackend` traduce un `BackendFeatures` (acelerador, idioma, hilos, VAD, prompt) a sus flags específicas — evita errores de flag.
4. **Descarga con libsoup 3.0**: streaming chunk-by-chunk, progreso, cancelación (`Gio.Cancellable`), resume (`Range:`), verificación SHA-256 (`GLib.Checksum`).

## Fase 4: Descargador de modelos (libsoup)

### 4.1 `src/models/model-downloader.ts` (nuevo)

Núcleo de descarga. Clase `ModelDownloader`:

- `download(entry, file, onProgress): Promise<void>`:
    - URL: `https://huggingface.co/${repo}/resolve/main/${filename}`.
    - Resume: si `<path>.part` existe, lee su tamaño con `query_info('standard::size')` y envía `Range: bytes=N-`; abre con `append_to_async`. Si no, `replace_async(REPLACE_DESTINATION)`.
    - Stream: `Soup.Session.send_async(msg, PRIORITY, cancellable)` → loop `inputStream.read_bytes_async(1MiB)` → `checksum.update(data)` → `out.write_bytes_async(bytes)`.
    - Progreso: throttled a 4 Hz, callback `onProgress(downloaded, total)`.
    - Cancelación: `Gio.Cancellable.cancel()`; deja `.part` para resume.
    - Verificación: `checksum.get_string()` === `file.sha256`. Si coincide, renombra `.part` → final; si no, borra y lanza error.
- `cancel(modelId)`: dispara el cancellable de esa descarga.
- Una `Soup.Session` compartida (long-lived, `user_agent: 'plane-asr'`).
- `Gio._promisify` en los métodos async de InputStream/OutputStream/File/Session al cargar el módulo.

## Fase 5: Auto-detección de GPU (Vulkan)

### 5.1 `src/extension/gpu-detector.ts` (nuevo)

- `detectVulkanGpus(): Promise<GpuInfo[]>`:
    - Ejecuta `vulkaninfo --summary` vía `Gio.Subprocess` (si está en PATH).
    - Parsea bloques `GPU0:`...`deviceName`/`deviceType`.
    - Para VRAM: ejecuta `vulkaninfo -j` (JSON) y lee `memoryHeaps` con flag `DEVICE_LOCAL_BIT`.
- `GpuInfo { index, name, type: 'discrete'|'integrated'|..., vramBytes }`.
- `pickOptimalDevice(gpus): number` — prefiere discrete con más VRAM.
- Caché en memoria (la detección es costosa, ~200ms).
- Fallback graceful: si `vulkaninfo` no está, devuelve `[]` y la UI muestra "no detectado".

### 5.2 Resolución del acelerador en tiempo de transcripción

`resolveAccelerator(settings, gpuDetector): {backendFlag?: string[], deviceIndex: number}`:

- `cpu` → transcribe-cli: `['--backend','cpu']`; whisper-cli: `['-ng']`.
- `vulkan` → transcribe-cli: `['--backend','vulkan','--device',String(idx)]`; whisper-cli: `['-dev',String(idx)]`.
- `auto` + `auto-detect-gpu` → si hay GPU Vulkan, usa vulkan; si no, cpu.

## Fase 6: Refactor de backends con features semánticas

### 6.1 `src/extension/asr-backends.ts` — ampliar

Agregar `BackendFeatures`:

```ts
interface BackendFeatures {
    accelerator: 'auto' | 'cpu' | 'vulkan';
    gpuDevice: number; // -1 = auto
    language: string; // 'auto' o ISO
    translate: boolean;
    threads: number; // 0 = auto (no emitir)
    vad: boolean; // solo whisper-cli
    initialPrompt: string; // '' = no emitir
}
```

Ampliar `BuildArgvOptions` con `features: BackendFeatures`. Cada `buildArgv` traduce a sus flags:

- **transcribe-cli**: `--backend`, `--device`, `--language`, `--translate`, `--target-language`, `--threads`, `--initial-prompt`. (VAD se ignora con warning.)
- **whisper-cli**: `-dev`/`-ng`, `-l`/`--language`, `-tr`, `-t`/`--threads`, `--prompt`, `--vad`.
- **nero-asr/custom**: features ignoradas (pasa directo).

Cada backend declara `supportedFeatures: Set` para que la UI muestre/oculte opciones.

## Notas de compatibilidad

- Usuarios con `modelParams` ya configurado: si `active-model-id` está vacío, se usa `modelParams` (retrocompatibilidad total).
- `nero-asr` y `custom` ignoran las features semánticas (no se rompen).
- El descargador es opt-in (nadie pierde su flujo actual).

## Fuera de alcance (no se implementan)

- Descarga de modelos ONNX/directorio (Handy los soporta; plane-asr solo usa GGUF con CLIs).
- Post-procesado LLM (Handy lo tiene; no solicitado).
- Token HF (los repos del catálogo son públicos; se deja un setting opcional futuro).
- Actualización en vivo del catálogo desde HF (catálogo embebido suficiente para v1).
