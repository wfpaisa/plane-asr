# Plan: Eliminar todos los backends excepto transcribe.cpp

## Resumen
Quedarse **únicamente** con el backend `transcribe-cli` (transcribe.cpp). Se eliminan `whisper-cli`, `nero-asr` y `custom`. Como transcribe.cpp no soporta VAD, se elimina también esa funcionalidad. Se simplifica pero **se mantiene la interfaz** de abstracción (`AsrBackend` / `ASR_BACKENDS` / `getBackend`) con un único elemento para minimizar el riesgo y los cambios en `transcriber.ts` y `asr-service.ts`.

## Cambios por archivo

### 1. `src/extension/asr-backends.ts`
- Eliminar del array `ASR_BACKENDS` las entradas `whisper-cli`, `nero-asr` y `custom` (queda solo `transcribe-cli`).
- Borrar la función `whisperCliFeatureArgs()` (ya sin usos).
- Eliminar el campo `vad` de `BackendFeatures`, de `NEUTRAL_FEATURES`, de `BackendCapabilities` y de la capacidad del backend `transcribe-cli` (su comentario "transcribe-cli has no VAD flag" desaparece).
- Quitar la rama `if (features.vad)` de `transcribeCliFeatureArgs()` y la mención a VAD en su doc-comment.
- `getBackend` y `parseArgs` se quedan como están.
- Quitar `customTemplate` de `BuildArgvOptions` (ya no lo usa ningún backend).

### 2. `src/extension/transcriber.ts`
- Quitar `customTemplate` de `_buildArgvOptions()` y su lectura del setting `custom-arg-template`.
- En `_resolveFeatures()`: quitar la línea `vad: this._settings.get_boolean(SETTINGS_KEYS.VAD_ENABLED)`.
- Actualizar el doc-comment del header que menciona "VAD".
- El resto de la lógica de `getBackend(...)` se mantiene.

### 3. `src/extension/asr-service.ts`
- Sin cambios funcionales necesarios: sigue usando `getBackend(backendId).defaultCliName` y `ASR_BACKEND`, que siguen existiendo. El `backendId` por defecto `'transcribe-cli'` es ahora el único válido.

### 4. `src/config/settings.ts`
- Eliminar `CUSTOM_ARG_TEMPLATE` y `VAD_ENABLED` de `SETTINGS_KEYS`.
- Quitar el campo `vad: false` mencionado en comentarios.

### 5. `schemas/org.gnome.shell.extensions.planeasr.gschema.xml`
- Eliminar las keys `<key name="custom-arg-template">` y `<key name="vad-enabled">`.
- Actualizar la `<description>` de `asr-backend` para que ya no mencione whisper/nero/custom.
- Se mantiene la key `asr-backend` (compat) pero su único valor útil es `transcribe-cli`.

### 6. `src/prefs/index.ts`
- Eliminar el `ComboRow` "ASR backend" y toda la lógica de `syncBackendRows` / el listener `changed::asr-backend` asociado al selector (ya que solo hay un backend, el selector no aporta nada). El setting `asr-backend` se fija a `transcribe-cli`.
- Eliminar `customTemplateRow` (entry "Custom arg template") y su binding a `CUSTOM_ARG_TEMPLATE`.
- Eliminar `vadRow` (switch VAD) y su binding a `VAD_ENABLED`; eliminar el grupo "Quality" si queda vacío (solo contiene VAD + prompt → se queda el prompt).
- Eliminar imports ya no usados: `ASR_BACKENDS`, y si aplica `getBackend`/`parseArgs` si dejan de usarse.
- El resto (modo CPU/GPU, dispositivo GPU, hilos, idioma, traducir, prompt, chunking, output, debug) se mantiene.

### 7. `src/prefs/models-page.ts`
- La línea `ctx.settings.set_string(SETTINGS_KEYS.ASR_BACKEND, entry.backend)` al hacer clic en "Use": ahora todos los modelos del catálogo son `transcribe-cli`, así que se puede simplificar a fijar siempre `'transcribe-cli'`, o dejar la línea (el `entry.backend` será siempre `transcribe-cli`). Se deja la asignación con valor fijo `'transcribe-cli'` para robustez.

### 8. `src/models/catalog.ts`
- Actualizar el doc-comment del campo `backend` (línea 33): ahora siempre es `'transcribe-cli'`.

### 9. `data/model-catalog.json`
- **Eliminar los 6 modelos Whisper** (`whisper-medium`, `whisper-large-v3-turbo`, `whisper-large-v3`, `whisper-small`, `whisper-base`, `whisper-tiny`) porque transcribe.cpp no puede correr la arquitectura Whisper.
- Quedan los modelos transcribe-cli (Parakeet/Nemotron/Canary/Qwen3/Moonshine/Voxtral/Cohere).

### 10. Validación
- `pnpm run build` (tsc typecheck) — debe pasar sin errores (es el gate de corrección).
- `pnpm run lint` — debe pasar.
- `glib-compile-schemas schemas` se ejecuta vía `make pack`; no se requiere manualmente aquí, pero se indica que el cambio de schema es coherente.

## Notas / Riesgo
- **Mantener la interfaz `AsrBackend`/`getBackend`** reduce drásticamente el riesgo: no hay que reescribir el ensamblado de argv en `transcriber.ts` ni el pre-flight de `asr-service.ts`.
- El setting `asr-backend` se conserva en el schema (con valor `transcribe-cli`) para no romper perfiles de usuario existentes; simplemente ya no hay selector UI.
- Usuarios con un `vad-enabled=true` o `custom-arg-template` previamente guardado: GSettings simplemente ignora keys inexistentes, no hay crash. El `asr-backend` antiguo tipo `whisper-cli` se seguiría leyendo pero `getBackend` cae al fallback (`ASR_BACKENDS[0]` = transcribe-cli), así que funciona.
