## Objetivo

Reemplazar el SpinRow numérico "GPU device index" por un **dropdown (Adw.ComboRow + Gtk.StringList)** poblado con las GPUs reales que reporta el binario configurado vía `--list-devices`, para que el índice seleccionado coincida exactamente con lo que `--device N` entiende (crítico para tu build CUDA, donde los índices de `vulkaninfo` no coinciden).

## Por qué `--list-devices` y no `vulkaninfo`

Comprobado en tu máquina: los índices difieren entre `vulkaninfo` (Intel=0, 5070Ti=1, 5060Ti=2) y el binario CUDA (5070Ti=0, 5060Ti=1, CPU=2). El flag `--device N` usa el índice interno del CLI, así que `--list-devices` es la única fuente autoritativa.

## Cambios

### 1. NUEVO `src/extension/device-lister.ts`

- Patrón estructural copiado de `gpu-detector.ts` (helper `runCapture` con `Gio.Subprocess` + `communicate_utf8_async`).
- `export interface DeviceInfo { index: number; name: string; kind: string; vramLabel: string; }`
- `parseListDevices(text: string): DeviceInfo[]` — parsea el formato:
    ```
    3 compute device(s):
      [0] NVIDIA GeForce RTX 5070 Ti
          name=CUDA0  kind=cuda  type=gpu  id=0000:01:00.0
          memory: 15.51 GiB total, 15.22 GiB free
    ```
    Regex: `^\s*\[(\d+)\]\s*(.+)$` para la cabecera de dispositivo, y para la línea de memoria `memory:\s*([\d.]+\s*\w+)\s*total`.
- `async function listDevices(cliPath: string): Promise<DeviceInfo[]>` — ejecuta `[cliPath, '--list-devices']`, filtra `[info] ggml_*` (logs de CUDA init), devuelve `[]` si el binario falta/falla (CPU-only bundled normalmente reporta solo el dispositivo CPU; está bien).
- No cachea (se llama bajo demanda desde la UI).

### 2. `src/prefs/index.ts` — reemplazar SpinRow por ComboRow dinámico

- **Quitar** el `Adw.SpinRow gpuRow` (líneas 379-391) y su `settings.bind(GPU_DEVICE, gpuRow, 'value', …)` (753-758).
- **Añadir** `gpuDeviceRow = new Adw.ComboRow({ title: 'GPU device', subtitle: 'Which GPU the CLI uses' })` con un `Gtk.StringList` que se pobla dinámicamente.
- Helper `refreshGpuDevices()` async:
    1. Resuelve `cliPath` para el `cli-mode` actual (espejo de `transcriber._resolveCliPath`: gpu → `CLI_PATH`; cpu → `resolveAutoCli(...)`).
    2. Si `cliPath` vacío o CPU-mode con binario bundled CPU-only → poblar con `['Auto']` y desactivar el row.
    3. `const devices = await listDevices(cliPath)`. Si vacío → `['Auto']` + subtitle "No devices detected".
    4. Poblar el StringList: `['Auto (let CLI choose)', ...devices.map(d => \`${d.index} · ${d.name} (${d.kind})\`)]`.
    5. Seleccionar el índice correspondiente al `gpu-device` actual (-1 → índice 0 = "Auto"; N → índice N+1 si existe, si no, "Auto").
- Sincronización manual (como `accelRow`): `notify::selected` → `settings.set_int(GPU_DEVICE, selected === 0 ? -1 : devices[selected-1].index)`.
- Se re-ejecuta `refreshGpuDevices()` cuando cambian `cli-mode`, `cli-path` o `asr-backend` (el binario puede cambiar).

### 3. Eliminar el switch "Auto-detect GPU" redundante

- El dropdown ya ofrece "Auto" con índices correctos. El switch `auto-detect-gpu` + detector `vulkaninfo` da índices que **no** coinciden con `--device N` en builds CUDA, así que es misleading. Lo quito de la UI.
- **Decisión (pregunta 2 quedó en "skip"):** conservo la **key GSetting `auto-detect-gpu`** y el `gpu-detector.ts` en el código (no romper instalaciones existentes / migraciones), pero elimino su UI y su uso en `transcriber._resolveGpuDevice`. Esto evita índices erróneos. Marcaré `_resolveGpuDevice` para que, en `accelerator='auto'`, devuelva siempre el `gpu-device` explícito (con -1 = sin flag), sin invocar el detector Vulkan.
- `refreshGpuInfo` (el `gpuInfoLabel`) se elimina; su información (nombres/VRAM) ya vive en el dropdown.

### 4. `src/extension/transcriber.ts` — simplificar `_resolveGpuDevice`

- Ahora que el usuario escoge el dispositivo explícito vía dropdown (o "Auto" = -1), la rama de auto-detección Vulkan pierde sentido:
    ```ts
    private async _resolveGpuDevice(accelerator: Accelerator): Promise<number> {
        // The prefs dropdown now lists real CLI devices; honor the explicit
        // choice (-1 = no --device flag, let the CLI pick device 0).
        return this._settings.get_int(SETTINGS_KEYS.GPU_DEVICE);
    }
    ```
- El comportamiento: `accelerator='auto'` + `gpu-device=-1` → sin flag (el CLI elige device 0, que es la GPU 0). `gpu-device=2` → `--device 2`. Consistente en transcribe-cli y whisper-cli (ambos gatean con `>= 0`).

### 5. No tocar el schema

- `gpu-device` (int, -1) y `auto-detect-gpu` (bool) se mantienen. Solo cambio la UI que los expone y el uso en runtime. Migración limpia: usuarios con valores previos los conservan; `-1` sigue siendo "Auto".

## Sensibilidad del dropdown

- Visible y habilitado solo cuando `accelerator ∈ {auto, vulkan}` Y `cli-mode='gpu'` (en CPU mode no hay GPU que elegir). Reutilizo la lógica actual en `syncAccel`.
